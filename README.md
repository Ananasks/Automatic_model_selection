# Classical Model Autoselector for Ionospheric Time Series

Автоматизированный ML-пайплайн для обучения, сравнения, выбора и дообучения классических моделей регрессии на временных рядах ионосферных параметров.
Проект оформлен как портфолио-кейс для позиции Junior Python / Junior ML Developer: он показывает базовые навыки работы с данными, построения ML-пайплайна, сравнения моделей и сохранения результатов экспериментов.

Основной акцент сделан на понятной и воспроизводимой логике для time-series задач:

- test-часть берётся из более позднего участка ряда, без случайного перемешивания;
- scaler обучается только на train-части, чтобы не было data leakage;
- каждая целевая переменная обучается и дообучается в своей директории артефактов;
- результаты сохраняются в виде моделей `.pkl` и Excel-отчётов для последующего анализа.

## Что делает проект

- Загружает временные ряды из CSV в двух форматах: с колонкой `datetime` или с парой колонок `date` + `time`.
- Создаёт календарные признаки: час, день недели, месяц, день года, неделя года и другие.
- Применяет HP-фильтр к целевой переменной для сглаживания временного ряда.
- Делит временной ряд хронологически: первые 80% выбранного интервала идут в train, последние 20% — в test.
- Обучает несколько моделей регрессии:
  - `LinearRegression`
  - `Lasso`
  - `MLPRegressor`
- Сравнивает модели по метрикам `R²`, `MAE`, `MAPE`.
- Автоматически выбирает лучшую модель по `R²`.
- Сохраняет обученные модели, scaler, список признаков и Excel-отчёты.
- Загружает лучшую модель для той же целевой переменной и дообучает её на новых временных участках.

## Логика пайплайна

1. CSV-файл приводится к единому datetime-индексу.
2. Для каждого наблюдения создаются календарные признаки.
3. Целевая переменная сглаживается HP-фильтром.
4. Выбранный диапазон дней делится хронологически на train/test.
5. `StandardScaler` обучается только на train-части.
6. Обучаются `LinearRegression`, `Lasso`, `MLPRegressor`.
7. Лучшая модель выбирается по `R²`.
8. Модель, scaler, список признаков и отчёты сохраняются в `trained_models/`.
9. На новых интервалах загружается лучшая модель для той же целевой переменной и выполняется дообучение.

## Ожидаемый формат данных

Скрипт поддерживает два варианта CSV.

Вариант 1:

```text
datetime,target_column,feature_1,feature_2,...
```

Вариант 2:

```text
date,time,target_column,feature_1,feature_2,...
```

Целевая колонка задаётся через `ExperimentConfig`:

```python
config = ExperimentConfig(
    file_path="data.csv",
    target_column="muf",
    day_start=50,
    day_stop=100,
    dataset_name="MUF",
)

trainer = ModelTrainer(config)
trainer.run()
```

## Основные классы

`ExperimentConfig` хранит настройки одного эксперимента:

- путь к CSV;
- целевую колонку;
- диапазон дней;
- имя папки для артефактов.

`ModelTrainer` отвечает за первичное обучение:

- загрузка и обработка данных;
- генерация временных признаков;
- хронологическое разделение на train/test;
- нормализация признаков без утечки test-данных;
- обучение набора моделей;
- выбор лучшей модели;
- сохранение моделей и отчётов.

`ModelFineTuner` отвечает за повторное использование лучшей модели:

- загрузка scaler, признаков и лучшей модели;
- подготовка нового участка данных;
- выравнивание признаков под сохранённую модель;
- дообучение модели на той же целевой переменной;
- расчёт метрик;
- сохранение дообученной версии.

## Разбор частей кода

Код разделён на несколько логических блоков, чтобы пайплайн было проще читать, запускать и расширять.

### 1. Настройки эксперимента

`ExperimentConfig` хранит параметры одного запуска:

- путь к CSV-файлу;
- название целевой колонки;
- диапазон дней для обучения;
- имя папки, куда сохраняются модели и отчёты.

Такой подход помогает не прописывать параметры вручную в разных частях кода и упрощает запуск нескольких экспериментов подряд.

### 2. Загрузка и подготовка данных

Функции `build_datetime_column()` и `load_time_series()` отвечают за чтение CSV и подготовку временного индекса.

Что происходит внутри:

- поддерживаются два формата времени: `datetime` или `date` + `time`;
- строки сортируются по времени;
- удаляются некорректные значения;
- проверяется наличие целевой колонки;
- к целевой переменной применяется HP-фильтр для выделения сглаженного компонента ряда.

Эта часть показывает базовую работу с реальными данными, где формат входного файла может отличаться.

### 3. Инженерия признаков

`add_time_features()` создаёт календарные признаки:

- час;
- минута;
- день недели;
- месяц;
- день года;
- номер недели;
- квартал.

Классические модели регрессии не понимают время напрямую, поэтому такие признаки помогают передать им сезонность и структуру временного ряда.

### 4. Разделение на train и test

`make_feature_target_split()` выбирает нужный диапазон дней, а `chronological_split()` делит данные на обучение и проверку.

Важная деталь: данные не перемешиваются. Train берётся из более ранней части ряда, test — из более поздней. Это ближе к реальной задаче прогнозирования, где модель проверяется на будущем участке данных.

### 5. Масштабирование признаков

`scale_features()` использует `StandardScaler`.

При первичном обучении scaler обучается только на train-части, а затем применяется к test-части. Это нужно, чтобы избежать data leakage: модель не должна получать информацию из проверочных данных до оценки качества.

### 6. Обучение и сравнение моделей

`ModelTrainer` запускает основной цикл обучения:

- создаёт набор моделей в `create_models()`;
- обучает `LinearRegression`, `Lasso` и `MLPRegressor`;
- оценивает каждую модель через `evaluate_regression()`;
- сравнивает результаты по `R²`, `MAE` и `MAPE`;
- выбирает лучшую модель в `select_best_model()`.

Этот блок показывает умение собрать базовый ML-эксперимент: обучить несколько моделей, сравнить метрики и автоматически выбрать лучший вариант.

### 7. Сохранение артефактов

После обучения сохраняются:

- модели в формате `.pkl`;
- `scaler.pkl`;
- список признаков `feature_names.pkl`;
- Excel-отчёты с метриками;
- информация о лучшей модели.

Это делает эксперимент воспроизводимым: модель можно загрузить позже без повторного обучения с нуля.

### 8. Дообучение модели

`ModelFineTuner` загружает лучшую сохранённую модель и дообучает её на новом временном интервале.

В этой части:

- загружаются сохранённые scaler, признаки и лучшая модель;
- новые признаки выравниваются под исходный список через `align_features()`;
- модель обучается на новом участке данных;
- качество снова проверяется на более поздней test-части;
- дообученная модель и отчёт сохраняются отдельно.

Эта логика показывает, как можно переиспользовать уже обученную модель и адаптировать её к новым данным.

### 9. Точка входа

`main()` описывает демонстрационный сценарий:

- запускает обучение для `absTEC`, `absCB` и `MUF`;
- выбирает лучшую модель для каждой целевой переменной;
- проводит несколько тестов дообучения на разных диапазонах дней;
- сохраняет все результаты в `trained_models/`.

Благодаря этому проект можно запустить одной командой и получить полный цикл: подготовка данных, обучение, выбор модели, дообучение и отчёты.
